# Griffin Fund, iOS

The phone is not the terminal and must not pretend to be.

Bloomberg's own mobile app does not ship Launchpad. It ships news,
Instant Bloomberg, market data, worksheets and alerts, and leaves the
dense multi-panel grid on the desk. The saved view travels; the layout
does not. Single-purpose tools survive as tools; whole functions do not.
The same logic governs here: a six-inch screen holds a reader, an alerter
and a messenger, and anything with columns belongs on the Mac.

## What is here

Two tabs, chosen because they are the two that work on a phone.

**Today** is the one Bloomberg does not have and the club needs most.
Their mobile alerts are market events; ours are obligations. It walks the
open research projects and collects everything the chase clock says is
actionable, rendering the server's own recommendation sentence rather
than inventing a second rule that could disagree with the Mac.

**Book** is the portfolio: the marked total and the holdings with the
day's move.

## What is deliberately absent

The outreach table, drafting, compliance screening and copy-to-send.
Those are desk work. The phone tells you Kanter replied; answering him
happens where there is a keyboard.

## Building

No XcodeGen or brew on the build machine, so `project.pbxproj` is
generated by `generate_project.py`, which discovers the Swift files on
disk and derives every object id from a hash of its name. Regenerating
with no source change produces a byte-identical file, so the diff on a
real change shows only the real change, and a missing tool cannot block
the build. Add a source file, then:

    python3 ios/generate_project.py

An earlier version of this paragraph claimed the script already existed
"in the commit that introduced it". It did not exist anywhere in the
repo, and adding a file meant hand-writing 24-hex-digit ids into five
places in the pbxproj. It exists now.

Version and build number live in `generate_project.py`, not in
`Info.plist`. The plist reads them back through `$(MARKETING_VERSION)`
and `$(CURRENT_PROJECT_VERSION)`; hardcoding them there alongside
`GENERATE_INFOPLIST_FILE = NO` is why the commit titled 0.1.1 shipped an
app that still called itself 0.1.0 build 1.

    xcodebuild -project ios/GriffinFund.xcodeproj -target GriffinFund \
      -sdk iphonesimulator -configuration Debug \
      CODE_SIGNING_ALLOWED=NO build

Running it needs a simulator runtime (`xcodebuild -downloadPlatform iOS`)
or a signed device build. TestFlight needs the paid membership on team
PW2VT56789, not just the Developer ID used for Mac notarization.

## Publishing to TestFlight

Two commands, and the second one is the whole trick.

    xcodebuild -project ios/GriffinFund.xcodeproj -scheme GriffinFund \
      -destination 'generic/platform=iOS' -configuration Release \
      -archivePath /tmp/GF.xcarchive archive \
      CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=

    xcodebuild -exportArchive -archivePath /tmp/GF.xcarchive \
      -exportPath /tmp/GF-out -exportOptionsPlist ios/ExportOptions.plist \
      -allowProvisioningUpdates

**The archive is unsigned on purpose and signing happens at export.**
Automatic signing during an archive reaches for a DEVELOPMENT profile,
which needs a registered device, and the team has none: "your team has
no devices from which to generate a provisioning profile". App Store
distribution needs no device, so the archive goes out bare and
`exportArchive` signs it with method `app-store-connect`. Pinning
`CODE_SIGN_IDENTITY=Apple Distribution` on the archive does not rescue
it either — Xcode rejects the combination outright as conflicting with
automatic signing.

**`destination` must be `upload`, not `export`.** With `upload`,
xcodebuild delivers straight to App Store Connect using the account
already signed into Xcode: no API key, no app-specific password, no
Transporter. With `export` you get a valid .ipa on disk and no way to
hand it over, which is a dead end worth naming — the archive it came
from records no team, so **Xcode's Organizer refuses it** with "No Team
Found in Archive" and cannot be used as a fallback. The .ipa is fine;
the archive simply is not distributable by hand.

Version and build number come from `generate_project.py`. Bump
`BUILD_NUMBER` before every upload — App Store Connect rejects a
duplicate build number outright.

## Rules carried over from the Mac client

- Decodables are written from the server handler, never from the JSX,
  and every field is optional: the app must render something useful
  against a payload that gained or lost a key.
- **Only a 401 ends a session.** A 429, or a 502 while Render wakes the
  dyno, keeps the login. That rule is the fix for the longest-running
  bug in this codebase and it is not to be relaxed here.
- The token lives in the keychain, never UserDefaults. It grants
  President-level access to the whole book, and a phone is lost far more
  often than a laptop.
- An empty list is good news and reads as good news, never as a failure
  to load.
